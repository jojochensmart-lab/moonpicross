# v0.2.0 算法与资源验收

Python 原始穷举与双后端 MoonBit 各 15,745 组棋盘和 141 组行候选集合一致。新增 Python 参考器用可分配空格组合枚举整行候选，交叉约束传播后分支整条线的候选，不依赖 MoonBit 的 DFS 或掩码缓存。其结果先和 3×3 完整 15,625 组直接穷举交叉校验，再分别对 JS 和 Wasm GC 的生成记录做唯一性计数。每后端成功的 1,449 个条目均确认只有一个解。20×20 提供来自两批种子的 252 个独立验证成功棋盘。

新增回归覆盖反射及转置后的候选次序、20×20 同候选分支和重复计数、零候选预算、后置非法线索、160 个随机非法线索与截断 JSON、负生成预算，以及实际耗尽 24 次尝试。已有测试覆盖无解、唯一、多解、已有首解仍返回 Budget、空和全填充的 30×30、畸形和超长 JSON、节点与扫描限制。深度 0 和 1 在需分支棋盘上产生可见的状态差异。内部 256 的最大深度由统一入口检查，样本未直接走到 256 层。

核心成功运行期间未发现栈溢出、死循环或预算超限。缓存至多每行一条，分支只复制棋盘。JS 运行 400 次重复 20×20 求解，单批 100 次后主动 GC。堆使用约 6.60–6.71 MB，没有观测到逐批增长。证据见 _build/v020-r14-memory.log。此记录无法证明 Native 或 Wasm GC 的峰值内存。
